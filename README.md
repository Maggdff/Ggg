# Smart Water Monitor

تطبيق أندرويد (Kotlin) يراقب عدّادَي ماء في كاميرا Hikvision واحدة (القناة 4) بتتبّع العقرب الكبير السفلي لكل عدّاد بـ OpenCV،
ويحسب «الزفات» (زفة عداد / زفة كاملة) وكمية البراميل ويسجّلها ويصدّرها CSV.

## الهيكل
- `app/src/main/java/.../core` — **نواة القياس** (Kotlin نقي بلا أندرويد، مُختبَرة على JVM):
  `MeterTracker` (تتبع العقرب + فك اللف + تعويض الاهتزاز)، `SwingEngine` (آلة حالات الزفات).
- `engine/` — قص ROI وتنعيم بـ OpenCV، وربط المصدر بالنواة والسجل.
- `camera/` — `VideoFileSource` (فيديو للاختبار)، و`src/hik` أو `src/nohik` حسب توفر Hikvision SDK.
- `verify/` — اختبار النواة على `testdata/meter.mp4` (`verify/run.sh`).

## البناء
- GitHub Actions (`.github/workflows/build-apk.yml`): عند كل push يُشغَّل اختبار الفيديو ثم يُبنى APK ويُرفع كـ artifact.
- محليًا: `./gradlew assembleDebug` (JDK 17 + Android SDK 34).

## الاتصال بالكاميرا (RTSP عبر libVLC — بلا حاجة لأي SDK)
يتصل التطبيق بـ `rtsp://المستخدم:كلمة_السر@IP:554/Streaming/Channels/<القناة>0<1|2>` (القناة 4 رئيسي = `401`، فرعي = `402`)،
وهو نفس مشغّل libVLC الذي اشتغل في RtspPersonTracker (يتحمّل H.265 بلا fmtp). تُلتقط الإطارات بالدقة الأصلية ~8 إطار/ث.
إن لم يعمل المسار الافتراضي ضع العنوان الكامل في حقل «عنوان RTSP كامل». الهاتف يجب أن يكون على نفس شبكة الكاميرا.

## Hikvision SDK (اختياري، لم يعد مستخدمًا في الاتصال)
الـ SDK مرخّص من Hikvision ولا يُوزَّع مع المشروع. حمّل «Android SDK» (HCNetSDK + PlayCtrl) من بوابة Hikvision للمطورين، ثم:
1. ضع `HCNetSDK.jar` و`PlayerSDK.jar` في `app/libs/` وملفات `.so` (مع مجلد `HCNetSDKCom`) في `app/src/main/jniLibs/<abi>/`.
2. أو لـ CI: ارفع zip (بالهيكل `libs/*.jar` و`jniLibs/<abi>/*`) إلى رابط خاص وضعه في سر المستودع `HIKVISION_SDK_URL`.
بدون ذلك يُبنى التطبيق ويعمل مع فيديو الاختبار، ويعلن صراحةً أن الاتصال بالكاميرا غير متاح.
> `HikSourceFactory` (src/hik) كُتب وفق واجهة SDK الرسمية لكنه **لم يُجرَّب** مع SDK أو كاميرا؛ قد يحتاج تعديل أسماء/تواقيع بحسب إصدارك.

## المعايرة (إلزامية لكل تركيب كاميرا)
شاشة «المعايرة والتحقق»: التقط لقطة، اختر العدّاد، المس **منتصف محور** العقرب الكبير السفلي ثم **حافة القرص الصغير**، تأكد أن الدائرتين الصفراوين
(حلقة البحث 0.33R–0.52R) فوق جسم العقرب لا فوق أرقام القرص، ثم «حفظ المعايرة» (يحفظ أيضًا مرجع تعويض الاهتزاز).
المعايرة الافتراضية مأخوذة من فيديو الاختبار (2560×1944) فقط.

## قواعد الحساب (وما فُسِّر منها)
- 360° = برميل، 180° = نصف برميل.
- بدء الزفة: تقدّم ≥ 6° خلال 2 ث. التوقف: تقدّم < 3° خلال 3 ث *مرصودة* (الانقطاع/فقدان التتبع لا يُحتسب توقفًا).
- زفة كاملة: العدّادان يتحركان معًا ويتوقفان بفارق ≤ 3 ث. إن توقف أحدهما قبل الآخر بأكثر من ذلك فلكلٍّ «زفة عداد». (الفارق 3 ث تفسيري، قابل للتعديل من الإعدادات؛ العدّادان لا يتوقفان في اللحظة نفسها تمامًا.)
- زفة أقل من 20° تُهمل (اهتزاز).
- **حدود معروفة**: انقطاع بث أطول من دورة كاملة للعقرب يُفقد الدورات الكاملة أثناء الانقطاع (تُعلَّم الزفة «تقريبية»). يُنصح ≥ 5 إطار/ث.
